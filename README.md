# CV / Resume Generator

Personal CV system: facts live in `data/`, layouts in `templates/`, and each job gets its own folder in `applications/`.
CVs are generated by AI (Claude chat or a coding agent) following the rules in `AGENTS.md`.

> **Private repo.** `data/` contains my phone number, my transcript, and my referee's contact details.

---

## Repo layout

```
cv/
├── AGENTS.md              # rules for any AI generating CVs (single source of rules)
├── CLAUDE.md              # contains "@AGENTS.md" so Claude Code reads the same rules
├── README.md
├── data/                  # SINGLE SOURCE OF TRUTH (YAML) + assets/photo.png + TODO.md
├── templates/             # LaTeX layouts: cv/, cv-picture/, resume/ (never edit)
├── applications/          # one folder per job: job_description.txt, cv.tex, .sty, notes.md, cv.pdf
├── sources/               # raw material: LinkedIn exports, old CVs, syllabus (reference only)
├── scripts/
│   ├── bundle.ps1         # Windows: bundle AGENTS.md + data + template into one file
│   └── bundle.sh          # Linux/macOS/Termux: same
├── .github/workflows/
│   └── build-cv.yml       # manual GitHub Actions build; commits cv.pdf into the folder
└── build/                 # generated bundles (gitignored)
```

Templates:

| Template     | Use for                                             | Length    |
| ------------ | --------------------------------------------------- | --------- |
| `cv-picture` | Bangladeshi employers / circulars expecting a photo | ≤ 2 pages |
| `cv`         | Academic, research, scholarships                    | ≤ 2 pages |
| `resume`     | Industry jobs and internships                       | 1 page    |

## Option A: Generate with Claude (incognito chat)

### 1. Create the folder and the bundle

**Windows**

```powershell
New-Item -ItemType Directory applications/YYYY-MM_company-role
powershell -ExecutionPolicy Bypass -File scripts/bundle.ps1 -Template cv-picture
```

**Linux / macOS / Termux**

```bash
mkdir -p applications/YYYY-MM_company-role
scripts/bundle.sh cv-picture
```

Save the circular into the new folder as `job_description.txt`, or keep the image/PDF there.

### 2. In the incognito chat

Attach `build/cv-bundle.txt` and the circular (text, image, or PDF), then send:

```
The attached bundle contains my AGENTS.md, all my data/*.yaml files, and the
cv-picture template. Follow AGENTS.md strictly to generate a CV for the
attached circular.

Output three complete files:
1. cv.tex
2. style-cv-picture-template.sty (with the portfolio line enabled)
3. notes.md
```

If you bundled a different template, change the template name in the prompt.

### 3. Save the outputs before closing the chat

Incognito chats are not saved. Put all three files into `applications/YYYY-MM_company-role/`.

### 4. Build

The PDF is always written next to `cv.tex` as `cv.pdf`.

- **VS Code:** open `cv.tex` and press **Ctrl+Alt+B** (LaTeX Workshop).
- **Terminal:** from the application folder:
  ```
  latexmk -pdf cv.tex && latexmk -c
  ```
  (`latexmk -c` removes the auxiliary files and keeps the PDF.)
- **Phone:** see [Building on GitHub](#building-on-github-phone--no-latex).

The photo path `../../data/assets/photo.png` is already set, so don't upload the photo to the chat.

### 5. Review

- Check `notes.md` for **Gaps**: things the job wants that aren't in my data.
- Ask for changes in the same chat ("cut to 2 pages", "drop the IoT project") and replace `cv.tex`.
- If it runs over the page limit, reduce the margins in the folder's copied `.sty` to 0.6in before cutting content.
- If the circular revealed new facts about me, add them to `data/`.

## Option B: Generate with an AI agent (Claude Code, Copilot, Cursor, Codex)

The agent works inside the repo, so no bundle is needed. It reads `AGENTS.md`
(Claude Code reads it through `CLAUDE.md`).

### 1. Create the folder

```powershell
New-Item -ItemType Directory applications/YYYY-MM_company-role   # Windows
mkdir -p applications/YYYY-MM_company-role                        # Linux/macOS
```

Save the circular as `job_description.txt` (or put the image/PDF in the folder).

### 2. Run the agent from the repo root

```
Follow AGENTS.md and generate a CV for applications/YYYY-MM_company-role.
Use the cv-picture template. Compile it and fix any LaTeX errors.
```

Optional extras:

- `Keep it to 2 pages.`
- `Also write a cover letter as cover_letter.md.`
- `Emphasize cybersecurity over ML.`

### 3. Review

- Read `notes.md`: template chosen, included/omitted entries, keywords covered, **Gaps**.
- Open `cv.pdf` in the application folder.
- Ask for fixes in the same session.
- If something is wrong because of a **rule** (e.g. a cert-only skill described as
  project work), fix `AGENTS.md`, not just the CV.

### 4. Commit

```bash
git add -A
git commit -m "Application: company-role"
```

## Building on GitHub (phone / no LaTeX)

The workflow `.github/workflows/build-cv.yml` runs **only when triggered manually**.
Pushing never starts a build.

1. Push the application folder.
2. On GitHub: **Actions → Build CV → Run workflow**.
3. Enter the folder name (e.g. `2026-11_company-role`) and run it.
4. After about a minute, the workflow commits `cv.pdf` into
   `applications/<folder>/`. Open it on GitHub directly, or run `git pull` to get it locally.

If the PDF hasn't changed since the last build, the workflow skips the commit.

## Platforms

### Windows

Use `scripts/bundle.ps1`, VS Code with LaTeX Workshop, and TeX Live or MiKTeX
(or the devcontainer).

### Linux / macOS

```bash
scripts/bundle.sh cv-picture
cd applications/YYYY-MM_company-role && latexmk -pdf cv.tex && latexmk -c
```

Needs `git`, and TeX Live for local builds (`sudo apt install texlive-full latexmk`).

### Android (Termux)

One-time setup:

```bash
pkg install git openssh
termux-setup-storage          # lets Termux access phone storage
git clone git@github.com:<you>/cv.git && cd cv
```

Per application:

```bash
mkdir -p applications/YYYY-MM_company-role
scripts/bundle.sh cv-picture
cp build/cv-bundle.txt ~/storage/downloads/   # so the Claude app can attach it
```

Use the Claude incognito chat as in Option A, save the outputs into the folder
(`nano`/`vim`, or copy from Downloads), then:

```bash
git add -A && git commit -m "Application: company-role" && git push
```

Build the PDF with the manual GitHub Actions workflow, then `git pull` to get `cv.pdf`.
No LaTeX is needed on the phone.

### Anywhere else (Overleaf)

Upload `cv.tex`, the `.sty`, and `data/assets/photo.png`.
Change the photo path in `cv.tex` to `photo.png`, then compile.

## Keeping data up to date

Always update `data/` first. Bundles and agents all read from there.

### Quick way: let AI do it

**Agent:**

```
Update data/ with this new info, following the existing schema in AGENTS.md:
<describe the change>
Add any open questions to data/TODO.md.
```

**Incognito chat:** attach `build/cv-bundle.txt`, describe the change, and ask for the
updated YAML entry. Then paste it into the right file yourself.

### What goes where

| Change                                 | File                  | What to do                                                                               |
| -------------------------------------- | --------------------- | ---------------------------------------------------------------------------------------- |
| New job / role / club position         | `experience.yaml`     | Add an entry with `end: present`; set `end` on the previous role                         |
| Role ended                             | `experience.yaml`     | Replace `present` with `YYYY-MM`                                                         |
| New project                            | `projects.yaml`       | Add an entry with tech, links, tags, priority, and 2–4 tagged bullets                    |
| Built something with a cert-only skill | `skills.yaml`         | Remove it from `cert_only_items` (or drop `cert_only`); add the project id to `evidence` |
| New certification                      | `certifications.yaml` | Add an entry; use `part_of` if it belongs to a specialization                            |
| Contest / CTF / award / fellowship     | `achievements.yaml`   | Add an entry with result, date, tags, priority                                           |
| Paper accepted / published / DOI       | `publications.yaml`   | Update `status`, add `links.doi`                                                         |
| New degree, CGPA, or thesis            | `education.yaml`      | Update the entry (and `coursework.yaml` for MSc courses)                                 |
| New transcript / grades                | `transcript.yaml`     | Add or update; course codes in `coursework.yaml` must match it                           |
| New blog post / writeup                | `writing.yaml`        | Add title, date, URLs, tags                                                              |
| New skill (with evidence)              | `skills.yaml`         | Add to the right category with `evidence` ids                                            |
| New reference                          | `references.yaml`     | Add name, position, contact, relation                                                    |
| Contact / links / summary changes      | `profile.yaml`        | Edit fields; add a new summary key if needed                                             |
| Found metrics (e.g. thesis numbers)    | the relevant entry    | Add a bullet with the number                                                             |
| Unsure about something                 | `TODO.md`             | Write it down instead of guessing                                                        |

### Entry rules

- Every entry needs an `id` (kebab-case), `tags` (vocabulary in `AGENTS.md`), and `priority` (high/medium/low).
- Bullets start with an action verb, include a number when possible, and carry their own tags.
- `note:` fields are instructions to the AI (e.g. "only for teaching roles", "never print rating").
- `show: false` hides a value from every CV.
- Dates are `YYYY-MM`; ongoing roles use `present`.

### After updating

1. `git commit -m "data: <what changed>"`
2. Mirror the change on LinkedIn and avro.bd so they stay consistent.
3. Nothing else to do: the next bundle or agent run picks it up automatically.
